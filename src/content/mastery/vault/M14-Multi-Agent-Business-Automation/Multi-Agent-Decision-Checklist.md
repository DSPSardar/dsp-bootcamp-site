# Multi-Agent Decision Checklist
Answer these before deciding a task needs more than one agent.

- [ ] Is this task actually several genuinely distinct jobs, not one job with several steps?
- [ ] Would a single, well-written Job Description struggle to hold all the needed context/rules at once?
- [ ] Is the added cost (tokens, latency, complexity, more failure points) clearly worth it for this use case?
- [ ] Have you tried making ONE agent work well first, and hit a real wall — not just an assumption it wouldn't work?

**If you answered "no" to any of the first three, or "no" to the last one: stick with a single agent.** Most of what this course builds — including every client-type in the Automation Blueprints above — is well-served by one agent done properly.
